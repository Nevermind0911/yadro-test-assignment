# Dungeon bot algorithm
---
Git-репозиторий с тестовым заданием на стажировку в **YADRO**-Импульс, команды разработки телеком-оборудования на C++.

Реализация алгоритма построения подземелья как связного графа по данным из текстового файла, а также проверки на нем алгоритма Алисы из тз. Алгоритм работает через виртуальный класс, что позволяет использовать любой другой алгоритм, работающий в описанных условиях. 

---
## Сборка и запуск

Требования: компилятор с поддержкой **C++17** (gcc/clang) и **CMake ≥ 3.10**.

```bash
cmake -B build
cmake --build build
```

Запуск:

```bash
./build/dungeon_bot <путь_к_входному_файлу>
```

Программа читает описание подземелья из переданного файла и пишет лог действий бота в `result.txt` (создаётся в текущей рабочей директории). При некорректных входных данных в `result.txt` записывается первая ошибочная строка и программа завершается с кодом `1`.

## Тесты

В директории `tests/` лежат пары файлов `<номер>-<имя>-input.txt` и `<номер>-<имя>-output.txt` — входные данные и ожидаемый результат.

Категории:
- `01-06` — корректные сценарии 
- `10-17` — некорректные входные данные (выход из диапазона, неверные имена ресурсов, асимметричный граф и т.д.)

Тесты интегрированы в CTest — после сборки запуск из директории `build`:

```bash
cd build
ctest --output-on-failure
```

CTest автоматически регистрирует каждую пару `*-input.txt` / `*-output.txt` как отдельный тест. Прогон работает через скрипт `cmake/run_test.cmake`: запускается `dungeon_bot` с входным файлом, потом содержимое `result.txt` сравнивается с ожидаемым. При расхождении CTest показывает diff.

## Структура проекта


Алгоритм бота отделён через интерфейс `BotStrategy` — можно подменить реализацию (`AliceBot`) на любую другую, не меняя симулятор.

## Алгоритмы

### Парсер

- Валидация: `N ∈ [1, 255]`, `M ∈ [2, 255]`, ресурсы ∈ `[0, 255]`
- Строка комнаты — 2 токена (`<id> <neighbors>`, ресурсы по умолчанию `0`) или 6 (с ресурсами)
- Граф должен быть явно двунаправленным: если в строке `i` указан сосед `j`, в строке `j` должен быть `i`
- При ошибке: первая проблемная строка выводится в `result.txt`, выход с кодом `1`

### Симулятор

`Room` — данные одной комнаты, `Simulator` — вектор комнат и состояние бота (позиция, еда, инвентарь). Поля приватные. Стратегии передаётся `const Simulator&`.

Учёт еды в `collect`: первый сбор в комнате бесплатный (проверка по `collected_[]`), последующие — 1 еда. После сбора `res_[i]` обнуляется, `collected_[i] = true` (для отображения `_` в `state`).

### Бот Алисы

- `pick_next_room` — первый непосещённый сосед (соседи отсортированы парсером → автоматически минимальный ID); иначе `bfs_nearest_unvisited`
- `pick_resource` — ресурс с максимальным `effective_value × quantity` (у целевого ценность удвоена)
- `bfs_nearest_unvisited` — BFS только через посещённые, непосещённые помечаются как цели-кандидаты, тай-брейк по меньшему ID; возвращается первый шаг пути

### Главный цикл

- **Исследование** (до `M/2` ходов): шаг, после  сбор лучшего ресурса. Ранний выход если все достижимые комнаты посещены
- **Возврат**: `bfs_return_path` строит путь (BFS из `0` + жадный спуск с тай-брейком по ID). Перед началом — добор излишков в текущей комнате (иначе оставшиеся там ресурсы теряются). Дальше по пути — сбор пока еды хватает на оставшиеся шаги
- В стартовой комнате — строка `result`
